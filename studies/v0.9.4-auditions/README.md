# v0.9.4 — prerecorded neural auditions

Three Kokoro voices × five fixed lines, generated by the actual HeadTTS 1.3.0 worker on CPU with FP32 weights. First gate: am_puck-1 WAV plus 26 cues validated before the remaining 14 were generated. No Edge TTS or paid inference. No permanent voice approved.

Open index.html through GitHub Pages. The review page imports only local playback code, loads saved MP3s and JSON cues, and reuses the existing stable speech atlas. No model, inference worker, external CDN or AI execution on the review device. Each voice also has a rendered H.264/AAC five-line MP4 with neutral leads/recoveries. WAV masters are 24 kHz, mono, 16-bit PCM.

## Evidence and limitations

`evidence/audio-validation.json`: real durations, PCM levels, clipping counts, SHA-256, FFmpeg decoding for all files. `evidence/*-render.json`: complete 24fps render timelines and exact uncompressed neutral recovery; all three MP4s decode. Contact boards show sampled actual renders. Browser QA is recorded separately when performed.

Original HeadTTS WAV bytes remain in `audio/*.wav`. Its encoder sets RIFF size to `32 + data length` instead of `36 + data length`. `masters/*.wav` repairs only this four-byte size field, preserving all samples. Raw engine timing is retained in every JSON. Puck Curious has three full-scale samples out of63,600; other takes have none. No silent repair or invented auditory verdict.

Timing comes from Kokoro's predicted token durations with HeadTTS's -10ms start/0ms end adjustment, not acoustic forced alignment. Visemes map to eight existing study poses; no newly approved artwork or redesign. Body remains still; articulation is discrete and approximate. Labels denote intended emotion, not a controllable emotional-performance parameter. All candidates use speed1 and identical words; no pitch processing. No listening assessment or artistic scores were performed by the agent because no audio-perception tool was available. The scorecard collects the director's own ratings using30/25/20/15/10 weights.

## Reproduce production (studio computer only)

Requires Node24, Python3 with NumPy/Pillow, FFmpeg, curl, and approximately2GB free memory beyond runtime overhead. Dependency lock includes HeadTTS1.3.0, Transformers.js4.3.2 and ONNX Runtime. Model revision and every downloaded file's SHA-256/size are pinned in `production/model-lock.json`. Upstream model weights are downloaded, not duplicated into the Git repository or served to mobile reviewers.

```
cd studies/v0.9.4-auditions/production
npm ci --ignore-scripts
python prepare.py ./model
node generate.mjs --first
```

Validate first WAV with wave/FFmpeg and its JSON timing before continuing. Then run `node generate.mjs` (existing outputs are retained), followed by `python finish.py`. On Linux x64 the npm package includes the CPU native runtime; `--ignore-scripts` avoided an unnecessary optional binary-feed timeout in this production session. Other platforms may need normal `npm ci`. Set DINO_MODEL to a model directory if stored elsewhere. Output byte determinism across hardware/runtime versions is not promised; saved originals are authoritative.

`generate.mjs` invokes the upstream worker directly, avoiding a production server and any inference on mobile. `finish.py` validates samples and timing, repairs RIFF headers, encodes MP3s and renders the full five-line previews. Original WAVs and timing are never overwritten by the generation script. No new GitHub Actions. Older studies retained.
