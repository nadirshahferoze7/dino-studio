# Release and review policy
Keep stable releases and rejected experiments separately; retain prior preview routes and source revisions. Use Git commits (and tags when supported) to record releases, branches for risky experiments, no destructive history rewrites. Each version manifest records character ID, source asset hashes, code commit, tool versions, clips, visual test evidence, known defects, approval status, next actions. Do not mark a version approved without owner approval. Review on a browser-accessible site, no download for routine review. The hosted dashboard should list version, date, status, changes, preview and recovery commit. GitHub Pages is a proposed hosting choice; site settings require verification before announcing a live URL.
