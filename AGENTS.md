# DINO Studio — permanent agent instructions

## Startup and handoff
- Read README, PROJECT_STATE, CHANGELOG, character Bible, identity JSON, asset registry and relevant skill before making changes. Inspect current Git tree and latest commits. Never rely on chat memory alone.
- Use the approved reference artwork as visual authority. A generated sheet, candidate model, or sample illustration cannot supersede it.
- Record each meaningful change in PROJECT_STATE.md and CHANGELOG.md, including files changed, exact reproduction instructions, test results, blockers, decisions and next task. Keep unapproved proposals separate from canon.
- Commit changes to GitHub with descriptive messages. Use non-destructive versioning; no force pushes or overwriting prior release assets. Keep previous previews at immutable version URLs. A failed experiment is archived and labelled rejected, not silently deleted.
- Preserve original asset bytes and SHA-256 hashes; distinguish derived layers, preview proxies, and approved originals. Do not assert binary availability without checking.
- For any release, supply browser-accessible preview where publishing access permits. User does not want download/install steps for ordinary review. GitHub is permanent source; site is visual review interface. Do not expose unpublished/private work beyond authorized repository visibility.
- Free, locally executable and AI-controllable methods first. No mandatory paid inference, external GPU quota, or manual user production tasks. Initial dependency downloads are acceptable. Never claim a tool was run, a site deployed, or a test passed without evidence.
- Prefer the approved image-based animation path over repeated procedural 3D likeness failures. Full 3D only if it demonstrably matches the approved face and silhouette and user approves.
- Quality gate: inspect actual output in motion, reference comparison, anatomy, continuity, no unintended mirroring, seams, clipping or detached limbs. Wave palm must face recipient, not nails/hand edge. Human creative approval is mandatory for official masters.
- User is a beginner and creative director; present simple visual results first, technical detail second. No unnecessary user tasks.
- Keep unrelated personal data and credentials out of this public repository.
